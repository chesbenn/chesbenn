# 02. Народный контроль сети

**Коротко:** любой человек — абонент, житель, сотрудник УК — может сфотографировать повреждение сети (оборванный кабель, открытый ящик, упавшую опору, ветку на линии) и отправить через бота или QR-код на оборудовании. Платформа сама определяет, чьё это оборудование, создаёт заявку и сообщает автору, что повреждение устраняется.

---

## Проблема
- Провайдер узнаёт о провисшем кабеле или открытом ящике, только когда всё уже сломалось.
- Люди видят повреждения каждый день, но не знают, кому сообщить и чьё это вообще.
- В домах висят кабели нескольких провайдеров, и даже монтажник не всегда отличит свой.

## Что делает
1. **Приём сообщений** из Telegram-бота, веб-формы и по **QR-наклейке** на ящике, муфте, опоре («Нашли повреждение? Сфотографируйте»).
2. **Определяет место:** геометка фото, геолокация телефона или QR-код (точно знает объект).
3. **Определяет, чьё оборудование:** ищет в графе ближайшие объекты провайдера (ящики, опоры, трассы кабеля) в радиусе 30 м.
4. **Классифицирует повреждение** по фото (ИИ): обрыв, провис, открытый ящик, повреждённая опора, ветка/дерево, вандализм, «не наше».
5. **Оценивает срочность:** есть ли активная авария рядом; сколько абонентов за этим объектом (через граф).
6. **Создаёт заявку** с фото, местом, объектом, абонентами под угрозой.
7. **Отвечает автору:** «Спасибо! Заявка №123, бригада приедет сегодня». Затем — «Исправлено» с фото после ремонта.
8. **Поощряет:** бонус на счёт абоненту за подтверждённое сообщение (настраивается).
9. **Отсеивает дубли:** несколько сообщений об одном месте → одна заявка.

## Кто пользуется
| Роль | Что делает |
|---|---|
| Абонент / житель | Отправляет фото, получает статус и бонус |
| Сотрудник УК | Сообщает о повреждениях в доме (через портал партнёров) |
| Диспетчер | Проверяет сомнительные сообщения, назначает бригаду |
| Монтажник | Получает заявку с фото и точкой на карте |
| Руководитель | Карта «горячих точек» вандализма и повреждений |

## Как работает
```
Фото + место (бот / веб / QR)
   → files: сохранить фото, извлечь EXIF (координаты, время)
   → geo: координаты → адрес, поиск объектов провайдера в радиусе 30 м
   → ИИ-классификация фото → тип повреждения + уверенность
   → проверка дублей: есть открытое сообщение в радиусе 50 м за 48 ч того же типа?
        да → добавить к существующему, ответить автору "уже знаем"
        нет → дальше
   → оценка срочности:
        абоненты за объектом (graph downstream)
        есть ли сейчас аварии рядом
        тип повреждения (обрыв > провис > открытый ящик)
   → tasks: заявка, приоритет, фото, объект
   → notify: автору "заявка №, срок"
   → после закрытия заявки: автору "исправлено" + фото после + бонус
```

## Данные
| Данные | Источник |
|---|---|
| Фото, координаты | Сообщение пользователя (EXIF или геолокация Telegram) |
| Объекты провайдера с координатами | Граф (ящики, опоры, узлы, трассы), импорт из Userside/ГИС |
| QR-коды объектов | Генерируются платформой для каждого объекта |
| Абоненты за объектом | Граф |

## Модель данных
```sql
CREATE TABLE field_report (
  id             BIGSERIAL PRIMARY KEY,
  channel        TEXT NOT NULL,            -- telegram, web, qr, partner_portal
  reporter_kind  TEXT NOT NULL,            -- subscriber, resident, uk, employee, anonymous
  reporter_ref   TEXT,                     -- id абонента / telegram id (хранится обезличенно)
  geom           geometry(Point, 4326),
  object_id      BIGINT REFERENCES graph_node(id),   -- найденный объект провайдера
  object_score   REAL,                     -- уверенность, что это наш объект
  damage_type    TEXT,                     -- cut, sag, open_box, pole, tree, vandalism, not_ours, other
  damage_score   REAL,
  description    TEXT,
  photo_ids      TEXT[],
  urgency        SMALLINT,                 -- 1..5
  subscribers_at_risk INT,
  task_id        BIGINT,                   -- заявка
  duplicate_of   BIGINT REFERENCES field_report(id),
  status         TEXT NOT NULL,            -- new, needs_review, accepted, rejected, fixed
  reward_rub     NUMERIC(10,2),
  created_at     TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE object_qr (
  code       TEXT PRIMARY KEY,             -- короткий код в QR
  object_id  BIGINT REFERENCES graph_node(id),
  printed_at TIMESTAMPTZ
);
```

## Правила и алгоритмы
- **«Наше или нет»:** ближайший объект в радиусе 30 м; если QR — 100%. Если объектов нет — статус `needs_review` («возможно, чужое»).
- **Классификация фото:** мультимодальная модель с короткой инструкцией и списком классов; ответ в JSON `{type, confidence, description}`. При уверенности < 0,6 — на ручную проверку.
- **Приоритет:** `urgency = f(тип, абоненты_за_объектом, активная_авария_рядом)`. Обрыв + > 50 абонентов = 5 (немедленно).
- **Защита от спама:** лимит 5 сообщений в сутки с одного аккаунта; фото без координат и без QR — только с ручной проверкой; повторяющиеся ложные — блокировка.
- **Бонусы** начисляются только после подтверждения монтажником.

## Интерфейсы
- **Бот:** «📸 Сообщить о повреждении» → фото → «отправить геолокацию» → готово.
- **QR-наклейка:** ссылка `https://сеть.провайдер.рф/q/AB12CD` → страница с камерой и кнопкой отправки (без регистрации).
- **Панель диспетчера:** лента сообщений, карта, кнопки «принять / отклонить / дубль».
- **Монтажник:** заявка с фото «до», после ремонта — обязательное фото «после».

## Интеграции
`files` (фото), `geo`, `graph`, `tasks`, `notify`, `llm-gateway` (классификация), биллинг (бонусы).

## Метрики успеха
- Доля повреждений, о которых узнали **до** аварии (цель — рост).
- Время от сообщения до устранения.
- Доля ложных/спам-сообщений (< 10%).
- Число активных «народных контролёров».

## Риски
- Персональные данные авторов: хранить минимум, не показывать монтажникам контакты без необходимости.
- Шутники и спам — лимиты и ручная проверка.
- Неточные координаты в многоэтажной застройке — QR-коды решают проблему.

## MVP (1–2 недели)
Бот: фото + геолокация → заявка с картой и ближайшим объектом → ответ автору при закрытии. ИИ-классификация и QR — вторым шагом.

## Как проверить
1. Отправить в бот фото с координатами рядом с ящиком из демо-графа → заявка привязана к ящику, указано число абонентов.
2. Второе фото того же места → помечено как дубль.
3. Закрыть заявку с фото «после» → автор получил сообщение и бонус.

## Зависимости
`graph` (объекты с координатами), `geo`, `files`, `tasks`, `notify`, `llm-gateway`.
