# 06. Конструктор тарифа и пробный период

**Коротко:** абонент сам собирает тариф ползунками и галочками — скорость, ТВ, статический IP, видеонаблюдение, защита от вирусов — и сразу видит цену. Новые клиенты могут попробовать интернет 7 дней бесплатно; система сама переводит их на платный тариф и отслеживает, кто может уйти.

---

## Проблема
- У провайдеров десятки устаревших тарифов, в которых путаются и абоненты, и операторы.
- Чтобы добавить опцию (например, белый IP), абонент звонит в поддержку.
- Крупные операторы привлекают пакетами, а малые не умеют гибко комбинировать услуги.
- Люди боятся менять провайдера: «а вдруг будет хуже».

## Что делает
1. **Конструктор:** скорость (100/300/500/1000), ТВ-пакет, домофон/видеонаблюдение, статический IP, антивирус/родительский контроль, аренда роутера, резервный LTE.
2. **Цена в реальном времени** со скидкой за комплект («ещё одна услуга — и скидка 10%»).
3. **Проверка доступности:** скорость 1 Гбит/с доступна только при PON/подходящем порте; ТВ — если есть мультикаст в доме (через граф).
4. **Применение без оператора:** смена тарифа в биллинге + новая скорость в шейпере + активация услуги (ТВ, IP) — сразу или с 1-го числа.
5. **Пробный период:** 7 дней бесплатно для новых адресов; монтаж по самоподключению или со скидкой.
6. **Контроль пробного периода:** качество связи, активность, обращения — прогноз «останется / уйдёт», вмешательство до конца пробного периода.
7. **Автоматический переход** на выбранный тариф с напоминанием за 2 дня и согласием.
8. **Подсказки:** «Вы платите за 500 Мбит/с, а используете максимум 60 — можно сэкономить» (честность повышает лояльность) или «Вы упираетесь в скорость по вечерам — попробуйте 500 бесплатно 3 дня».

## Кто пользуется
| Роль | Что делает |
|---|---|
| Абонент | Собирает тариф, меняет опции, пробует |
| Маркетолог | Настраивает опции, цены, скидки, правила пробного периода |
| Оператор | Помогает собрать тариф по телефону |
| Руководитель | Видит, какие комбинации покупают и сколько они приносят |

## Как работает
```
Абонент открывает конструктор
  → API: каталог опций + правила совместимости + доступность по адресу (graph)
  → расчёт цены (движок правил ценообразования)
  → "Подключить" → проверка баланса / согласия на условия (версия оферты)
  → событие bill.tariff.change_requested
  → биллинг: новая версия подписки (сразу / с даты)
  → bill.tariff.changed → сетевой слой: RADIUS CoA / шейпер (скорость), ТВ-платформа, IP-пул
  → подтверждение абоненту

Пробный период
  → заявка с пометкой trial (дата начала/конца)
  → ежедневно: score = f(активность, QoE, обращения, оплата не настроена)
  → день 5: напоминание + предложение выбрать тариф
  → если score низкий: задача оператору "позвонить, узнать, что не так"
  → день 7: согласие есть → платный тариф; нет → ограничение скорости + предложение
```

## Модель данных
```sql
CREATE TABLE offer_option (
  code        TEXT PRIMARY KEY,          -- speed_300, tv_basic, static_ip, cctv_1, av_family, lte_backup
  group_code  TEXT NOT NULL,             -- speed, tv, ip, security, devices, backup
  name        TEXT NOT NULL,
  price_month NUMERIC(10,2) NOT NULL,
  requires    JSONB,                     -- {"access": ["pon"], "multicast": true}
  conflicts   TEXT[],                    -- взаимоисключающие опции
  provisioning JSONB                     -- что сделать в сети: {"radius_profile": "300M"}
);

CREATE TABLE bundle_rule (
  id          BIGSERIAL PRIMARY KEY,
  condition   JSONB NOT NULL,            -- {"min_groups": 3}
  discount_pct NUMERIC(5,2) NOT NULL,
  valid_from  DATE, valid_to DATE
);

CREATE TABLE subscription_config (
  service_id  BIGINT NOT NULL,
  version     INT NOT NULL,
  options     TEXT[] NOT NULL,
  price_month NUMERIC(10,2) NOT NULL,
  effective_from TIMESTAMPTZ NOT NULL,
  source      TEXT,                      -- constructor, operator, migration
  PRIMARY KEY (service_id, version)
);

CREATE TABLE trial (
  service_id  BIGINT PRIMARY KEY,
  starts_at   TIMESTAMPTZ NOT NULL,
  ends_at     TIMESTAMPTZ NOT NULL,
  chosen_config TEXT[],
  score       REAL,
  outcome     TEXT                       -- converted, declined, extended
);
```

## Правила
- Изменения, уменьшающие цену, вступают с начала следующего расчётного периода; увеличивающие — сразу (с пересчётом).
- Пробный период — один на адрес в 12 месяцев (защита от злоупотреблений).
- Подсказки об экономии показываются не чаще раза в квартал.
- Старые тарифы не удаляются: абоненты остаются на них, пока сами не перейдут (версии).

## Интерфейсы
- **Mini App / кабинет:** ползунок скорости, карточки опций, итоговая цена, кнопка «подключить».
- **Сайт:** конструктор для новых клиентов → проверка адреса (модуль 04) → запись (модуль 05).
- **Маркетолог:** редактор каталога опций и скидок, A/B-тест цен.
- **Отчёт:** популярные комбинации, выручка, конверсия пробного периода.

## Интеграции
Биллинг (подписки, цены), RADIUS/шейпер (CoA), ТВ-платформа (Microimpuls/24ТВ/Смотрёшка), IP-пулы, `graph` (доступность), модули 04 и 05, прогноз оттока.

## Метрики
- Доля смен тарифа без оператора.
- Рост ARPU за счёт опций.
- Конверсия пробного периода (цель > 60%).
- Отток в первые 90 дней.

## Риски
- Сложный каталог отпугивает — по умолчанию показывать 3 готовых набора и кнопку «собрать свой».
- Если сетевой слой не применил изменения, абонент платит за то, чего нет — обязательная проверка применения и откат при ошибке.

## MVP (2–3 недели)
Каталог из 5–6 опций, расчёт цены, смена скорости через CoA, заявка оператору на прочие опции. Пробный период — вторым шагом.

## Как проверить
1. Собрать 300 Мбит/с + ТВ + статический IP → цена со скидкой за комплект; после подтверждения в симуляторе скорость = 300, IP выдан.
2. Выбрать 1 Гбит/с на Ethernet-адресе → опция недоступна с объяснением.
3. Пробный период с низкой активностью → на 5-й день задача оператору.

## Зависимости
Биллинг (или свой биллинг-движок), RADIUS CoA, `graph`, `notify`, модули 04, 05.
