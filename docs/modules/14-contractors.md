# 14. Контроль подрядчиков-монтажников

**Коротко:** при нехватке своих монтажников провайдеры всё чаще отдают работы подрядчикам и бригадам-сдельщикам. Модуль даёт им ограниченный доступ к заявкам, принимает работу по фото и автоматическим проверкам сети, считает оплату за каждую работу и рейтинг качества. Провайдер платит за результат, а не за «сказали, что сделали».

---

## Проблема
- Своих монтажников не хватает (по исследованию — больше половины провайдеров описывают ситуацию с кадрами как тяжёлую); подрядчики выручают, но их работу трудно контролировать.
- Оплата сдельщикам считается вручную по их же отчётам — переплаты и споры.
- Качество разное: повторные выезды из-за плохой работы подрядчика оплачиваются дважды.
- Подрядчики получают слишком широкий доступ к данным абонентов и системам.

## Что делает
1. **Профили подрядчиков:** организация/самозанятый, бригады, навыки, зоны, расценки, документы (договор, допуски).
2. **Выдача работ:** заявки в их зоне через то же приложение монтажника (PWA), с ограниченными данными (адрес, время, задача, контакт абонента только на время работы).
3. **Приёмка работ автоматически:**
   - фото «до/после» по чек-листу (ИИ-проверка: видно ли маркировку, аккуратность укладки, нет ли петель);
   - проверка сети: ONU зарегистрировалась, уровень сигнала в норме, сессия поднялась, скорость соответствует тарифу;
   - списание материалов (сколько кабеля/коннекторов) в пределах норм;
   - отсутствие повторных обращений и аварий по адресу в течение 72 часов (проверяется автоматически).
4. **Расчёт оплаты:** прайс по типам работ × принятые работы − удержания (переделки, перерасход материалов) + надбавки (срочно, ночь).
5. **Гарантия:** повторная заявка по тому же адресу в течение 30 дней из-за качества монтажа → работа не оплачивается/удерживается.
6. **Рейтинг:** качество, скорость, повторные выезды, пунктуальность → больше или меньше работ.
7. **Документы:** акты выполненных работ, реестр для оплаты самозанятым (с чеками «Мой налог»), выгрузка в 1С.

## Кто пользуется
| Роль | Что делает |
|---|---|
| Подрядчик / бригадир | Берёт работы, отчитывается, видит свои начисления |
| Диспетчер | Распределяет работы между своими и подрядчиками |
| Контролёр качества | Разбирает спорные приёмки |
| Бухгалтер | Акты, реестры оплат, проверка чеков самозанятых |
| Руководитель | Стоимость работ, качество подрядчиков |

## Как работает
```
Назначение
  → заявка → диспетчер (tasks) → исполнитель = свой или подрядчик (по зоне, загрузке, рейтингу, цене)
  → подрядчику: приложение показывает минимум данных; контакт абонента — маскированный звонок

Выполнение
  → чек-лист по типу работы: фото на шагах (щиток до, трасса, коннектор, ONU, после), материалы
  → кнопка "готово" →

Автоматическая приёмка
  → сеть: проверка через граф/коннекторы:
        PON: ONU online, Rx в диапазоне [-27; -8] дБм, без ошибок 15 мин
        Ethernet: линк 1G/100M, нет ошибок CRC на порту
        сессия RADIUS поднялась, скорость теста ≥ 80% тарифа (если есть тест с CPE)
  → фото: ИИ-проверка по чек-листу (каждое фото — на месте, нечёткие отклоняются)
  → материалы: списание в нормах по типу работы (±20%)
  → контроль 72 ч: сессия абонента стабильна, нет ошибок на порту/ONU, нет обращений по адресу
  → всё ок → accepted; иначе → needs_review (контролёр) или rework (переделка)

Оплата
  → период (неделя/месяц) → Σ accepted × расценка + надбавки − удержания
  → акт → подпись подрядчиком в приложении → реестр в 1С/банк
  → самозанятые: проверка чека через API ФНС «Мой налог»

Гарантия
  → новая заявка по адресу в 30 дней с причиной из списка "монтаж" → удержание
```

## Модель данных
```sql
CREATE TABLE contractor (
  id          BIGSERIAL PRIMARY KEY,
  legal_kind  TEXT NOT NULL,             -- company, ip, self_employed
  name        TEXT NOT NULL,
  inn         TEXT,
  zones       BIGINT[],
  skills      TEXT[],
  rate_card   JSONB NOT NULL,            -- {"connect_pon": 1800, "repair": 900, ...}
  rating      REAL,
  status      TEXT NOT NULL              -- active, paused, blocked
);

CREATE TABLE work_acceptance (
  task_id        BIGINT PRIMARY KEY,
  contractor_id  BIGINT REFERENCES contractor(id),
  technician_id  BIGINT,
  network_check  JSONB,                  -- {"onu_online": true, "rx_dbm": -21.3, "errors": 0}
  photo_check    JSONB,                  -- [{"step": "connector", "ok": true, "note": ""}]
  materials      JSONB,                  -- [{"sku": "fo_drop_m", "qty": 42, "norm": 40}]
  stable_72h     BOOLEAN,                -- 72 часа без проблем по данным сети
  status         TEXT NOT NULL,          -- pending, accepted, needs_review, rework, rejected
  amount         NUMERIC(10,2),
  withheld       NUMERIC(10,2),
  reason         TEXT
);

CREATE TABLE contractor_payout (
  id            BIGSERIAL PRIMARY KEY,
  contractor_id BIGINT REFERENCES contractor(id),
  period_from   DATE, period_to DATE,
  total         NUMERIC(12,2),
  act_file_id   TEXT,
  signed_at     TIMESTAMPTZ,
  receipt_checked BOOLEAN,               -- чек самозанятого проверен
  paid_at       TIMESTAMPTZ
);
```

## Правила
- Подрядчик не видит ФИО, паспорт, баланс абонента; телефон — только через маскированный звонок в окно работ.
- Работа без фото на обязательных шагах не принимается автоматически.
- Рейтинг = 0,4 × доля приёмок с первого раза + 0,3 × (1 − повторные выезды) + 0,2 × стабильность через 72 ч + 0,1 × пунктуальность.
- Рейтинг < порога → меньше работ; три переделки подряд → пауза и разбор.

## Интерфейсы
- **Приложение монтажника** (то же, что для своих) с ограниченным режимом.
- **Кабинет подрядчика:** мои работы, статусы приёмки, начисления, акты.
- **Контроль качества:** очередь `needs_review`, фото и данные сети рядом.
- **Бухгалтерия:** реестр оплат, экспорт.

## Интеграции
`tasks`, `files`, `llm-gateway` (проверка фото), коннекторы OLT/коммутаторов/RADIUS (проверка сети), склад (материалы), 1С, API «Мой налог» (проверка чеков), модуль 09 (сдача снятого оборудования).

## Метрики
- Доля работ, принятых автоматически.
- Повторные выезды по вине монтажа (снижение).
- Стоимость работы подрядчика vs своего монтажника.
- Споры по оплате (снижение).

## Риски
- Подрядчики сопротивляются фотоотчётам — чек-лист короткий (4–6 фото), выгода — быстрая и предсказуемая оплата.
- Ошибки ИИ-проверки фото — спорные случаи всегда смотрит человек.

## MVP (2 недели)
Подрядчики с ограниченным доступом к заявкам + проверка сети после «готово» + фото по чек-листу (без ИИ) + расчёт оплаты по прайсу. ИИ-проверка фото и гарантийные удержания — вторым шагом.

## Как проверить
1. Подрядчик закрывает подключение, ONU онлайн с Rx −21 дБм, фото на месте → `accepted`, сумма начислена.
2. ONU с Rx −29 дБм → `rework` с причиной «низкий сигнал».
3. Повторная заявка через 10 дней по тому же адресу с причиной «плохой коннектор» → удержание в следующем расчёте.

## Зависимости
`tasks`, `auth` (внешние роли), `files`, `graph`, коннекторы сети, склад, модуль 09, `llm-gateway`.
