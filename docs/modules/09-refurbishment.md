# 09. Восстановление и повторная выдача б/у оборудования

**Коротко:** роутеры, ONU и ТВ-приставки, которые вернули ушедшие абоненты или сняли при замене, проходят через понятный конвейер: приёмка → тест → сброс и перепрошивка → оценка → снова на склад. Платформа знает историю каждого устройства, его состояние и сколько денег сэкономлено.

---

## Проблема
- Возвращённое оборудование копится в коробках: неизвестно, рабочее ли оно, какая прошивка, чьи настройки внутри.
- Новое оборудование подорожало (параллельный импорт, +25% и 2–3 месяца доставки), а б/у простаивает.
- Ставят абоненту «проверенный» роутер, который через неделю ломается, — повторный выезд.
- Не возвращают оборудование ушедшие абоненты — никто не отслеживает.

## Что делает
1. **Учёт возврата:** при расторжении договора — задача «забрать оборудование» (если оно в аренде), напоминания абоненту, удержание залога/стоимости.
2. **Приёмка:** сканирование серийного номера/QR → карточка устройства с историей (у кого стояло, сколько, какие проблемы были — из графа и заявок).
3. **Автотест на стенде:** устройство подключается к тестовому порту → платформа сама проверяет: загружается, поднимает PON/Ethernet, уровень сигнала, Wi-Fi, скорость, температура.
4. **Сброс и прошивка:** сброс к заводским, установка «эталонной» прошивки (через ACS/TFTP), удаление персональных данных прежнего абонента.
5. **Оценка класса:** A (как новое), B (рабочее, косметика), C (только на запчасти/утиль) — по тестам и осмотру (фото).
6. **История надёжности модели и партии:** «эта модель ONU после восстановления ломается в 3 раза чаще» → не выдавать её повторно.
7. **Выдача:** при заявке на подключение склад предлагает сначала устройство класса A из восстановленных (если политика разрешает).
8. **Экономика:** сколько устройств восстановлено, сколько сэкономлено на закупке.

## Кто пользуется
| Роль | Что делает |
|---|---|
| Кладовщик / техник стенда | Принимает, тестирует, сортирует |
| Монтажник | Сдаёт снятое, получает восстановленное |
| Руководитель | Экономия, качество, решения о закупках |
| Абонент | Получает напоминание о возврате оборудования |

## Как работает
```
Возврат
  → sub.terminated → есть оборудование в аренде? → задача "забрать" + напоминания
  → монтажник/абонент сдаёт → скан → device.status = received

Тестовый стенд (Raspberry Pi / мини-ПК + управляемый коммутатор + тестовый PON-порт)
  → скан серийника → стенд получает профиль модели (какие тесты)
  → тесты (скрипт на стенде, результаты в API):
        ONU: регистрация на тестовом OLT, Rx/Tx мощность, температура, uptime 10 мин без ошибок
        Роутер: загрузка, DHCP/PPPoE, Wi-Fi 2.4/5 ГГц (сканер на стенде), iperf скорость LAN/WAN
        ТВ-приставка: загрузка, мультикаст-поток
  → сброс к заводским + эталонная прошивка (ACS/TFTP/SSH по модели)
  → проверка, что персональные настройки удалены (нет старого SSID/PPPoE-логина)
  → фото корпуса (опционально ИИ-оценка косметики)
  → класс A/B/C → место на складе

Выдача
  → заявка на подключение → склад предлагает восстановленное класса A
  → установка → в графе новая привязка, история продолжается
  → если сломалось в течение 30 дней → счётчик "ранний отказ" модели/партии
```

## Модель данных
```sql
CREATE TABLE device (
  id            BIGSERIAL PRIMARY KEY,
  serial        TEXT UNIQUE NOT NULL,
  mac           MACADDR,
  model         TEXT NOT NULL,
  batch         TEXT,                     -- партия поставки
  purchased_at  DATE,
  purchase_cost NUMERIC(10,2),
  ownership     TEXT NOT NULL,            -- company_rent, company_sold, subscriber_own
  status        TEXT NOT NULL,            -- in_stock, installed, to_collect, received, testing,
                                          -- ready, repair, scrap, lost
  grade         CHAR(1),                  -- A, B, C
  firmware      TEXT,
  location      TEXT,                     -- склад/машина/абонент
  graph_node_id BIGINT REFERENCES graph_node(id)
);

CREATE TABLE device_history (
  device_id   BIGINT REFERENCES device(id),
  at          TIMESTAMPTZ NOT NULL DEFAULT now(),
  event       TEXT NOT NULL,              -- installed, removed, returned, tested, flashed, graded, failed
  subscriber_ref TEXT,
  data        JSONB
);

CREATE TABLE device_test (
  id         BIGSERIAL PRIMARY KEY,
  device_id  BIGINT REFERENCES device(id),
  bench_id   TEXT,
  results    JSONB NOT NULL,              -- {"boot": true, "rx_dbm": -19.4, "wifi5": true, "lan_mbps": 941}
  passed     BOOLEAN NOT NULL,
  at         TIMESTAMPTZ DEFAULT now()
);
```

## Правила
- Класс A: все тесты пройдены, нет ранних отказов в истории, возраст < 4 лет.
- Класс B: тесты пройдены, есть косметика или возраст 4–6 лет — выдавать только с согласия/скидкой или на временную замену.
- Класс C: тест не пройден или ≥ 2 отказов в истории → запчасти/утиль.
- Модель с ранними отказами восстановленных > 2× от новых → повторная выдача блокируется.
- Персональные данные прежнего абонента должны быть удалены — без этого устройство не получает статус `ready`.

## Интерфейсы
- **Экран стенда:** сканер → прогресс тестов → итог и класс → печать наклейки.
- **Склад:** остатки по моделям и классам, что ждёт теста.
- **Возвраты:** кто должен вернуть, сколько дней, сумма.
- **Отчёт:** восстановлено, выдано повторно, экономия, ранние отказы по моделям.

## Интеграции
Склад/ТМЦ, `graph`, `tasks`, ACS (GenieACS) и TFTP для прошивки, тестовый OLT-порт, биллинг (удержания за невозврат), модуль 14 (подрядчики сдают оборудование).

## Метрики
- Доля выдач восстановленным оборудованием.
- Экономия на закупке в месяц.
- Ранние отказы восстановленного vs нового.
- Доля возвращённого оборудования от ушедших абонентов.

## Риски
- Стенд требует начальной настройки под каждую модель — начать с 3–5 самых массовых.
- Абоненты могут негативно воспринимать б/у — прозрачно указывать в условиях аренды; класс A — «проверено и восстановлено».

## MVP (2 недели)
Учёт устройств по серийнику с историей + задача «забрать при расторжении» + ручной чек-лист теста и класс. Автоматический стенд — вторым шагом.

## Как проверить
1. Расторгнуть договор с арендованной ONU → задача «забрать» и напоминания.
2. Принять ONU, провести тест на симуляторе стенда → класс A, статус `ready`.
3. Выдать её, через 10 дней отказ → счётчик ранних отказов модели увеличился.

## Зависимости
Склад, `graph`, `tasks`, `notify`, ACS/TFTP, тестовый стенд (оборудование ~30–50 тыс. ₽).
