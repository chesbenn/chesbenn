# 05. Онлайн-запись на монтаж

**Коротко:** абонент сам выбирает удобное время подключения или ремонта, как запись к врачу: «завтра 10:00–12:00» или «четверг 18:00–20:00». Система показывает только реальные свободные окна с учётом монтажников, их навыков, района, материалов и дороги. Никаких «ждите звонка».

---

## Проблема
- Диспетчер обзванивает абонентов, чтобы согласовать время; половина не берёт трубку, многие забывают и не открывают дверь.
- Монтажники ездят по городу хаотично, теряя часы на дорогу.
- Абонент ждёт «в течение дня» и злится.
- Нет понимания, сколько реально заявок можно взять на неделю вперёд.

## Что делает
1. **Показывает свободные окна** (по 2 часа) на 7–14 дней вперёд — в боте, Mini App, на сайте, в экране оператора.
2. **Учитывает:** график монтажников, их навыки (PON, Ethernet, бизнес, ТВ), район, длительность работы, время дороги, наличие оборудования на складе/в машине.
3. **Бронирует окно** и создаёт заявку с назначенным монтажником.
4. **Напоминает** абоненту за сутки и за 2 часа; кнопка «перенести» / «отменить».
5. **Сообщает «монтажник выехал»** и примерное время прибытия; ссылка на трекинг (по желанию).
6. **Перестраивает расписание** при срочных авариях: предлагает абонентам перенос с бонусом, а не просто «не приехали».
7. **Собирает оценку** после визита (1–5 звёзд + комментарий).
8. **Уплотняет маршрут:** окна в одном районе предлагаются в первую очередь, когда монтажник уже там.

## Кто пользуется
| Роль | Что делает |
|---|---|
| Абонент | Выбирает и переносит время, получает напоминания |
| Оператор | Записывает абонента по телефону в тот же календарь |
| Диспетчер | Видит загрузку, правит расписание, обрабатывает срочное |
| Монтажник | Видит свой маршрут на день в приложении |
| Руководитель | Загрузка бригад, «неявки», среднее ожидание |

## Как работает
```
Запрос окон {адрес, тип работы}
  → тип работы → длительность (подключение PON 90 мин, ремонт 45 мин, бизнес 180 мин)
                 и требуемые навыки
  → кандидаты-монтажники: навык + зона обслуживания + рабочий день
  → для каждого дня и каждого окна:
        вместимость = рабочее время − уже забронированные работы − дорога
        дорога = время от предыдущей точки маршрута (OSRM/матрица времени)
        проверка материалов: ONU/роутер есть на складе или в машине
  → оценка окна: меньше дороги и плотнее район → выше в списке
  → вернуть 6–10 лучших окон
Бронь
  → блокировка окна (Redis lock, 10 мин на подтверждение)
  → tasks: заявка + назначение + резерв материалов (склад)
  → notify: подтверждение, напоминания
День работ
  → утром: оптимизация порядка визитов внутри окон (VRP с окнами времени)
  → монтажник нажал "выехал" → абоненту "мастер в пути, ~25 мин"
  → завершение → оценка
```

## Данные
| Данные | Источник |
|---|---|
| Монтажники, навыки, графики, зоны | Справочник персонала / tasks |
| Длительность работ по типам | Справочник + статистика фактических длительностей |
| Время в пути | OSRM (свой сервер на данных OSM) |
| Остатки оборудования | Склад |
| Адрес и тип подключения | Граф, модуль 04 |

## Модель данных
```sql
CREATE TABLE technician (
  id          BIGSERIAL PRIMARY KEY,
  name        TEXT NOT NULL,
  skills      TEXT[] NOT NULL,          -- pon, ethernet, business, tv, repair
  zones       BIGINT[],                 -- полигоны районов (geo)
  home_geom   geometry(Point, 4326),    -- точка старта дня
  is_contractor BOOLEAN DEFAULT false   -- подрядчик (модуль 14)
);

CREATE TABLE work_shift (
  technician_id BIGINT REFERENCES technician(id),
  day           DATE,
  starts        TIME,
  ends          TIME,
  PRIMARY KEY (technician_id, day)
);

CREATE TABLE job_type (
  code          TEXT PRIMARY KEY,        -- connect_pon, connect_eth, repair, business, tv
  duration_min  INT NOT NULL,
  skills        TEXT[] NOT NULL,
  materials     JSONB                    -- [{sku, qty}]
);

CREATE TABLE booking (
  id            BIGSERIAL PRIMARY KEY,
  task_id       BIGINT NOT NULL,
  technician_id BIGINT REFERENCES technician(id),
  slot_start    TIMESTAMPTZ NOT NULL,
  slot_end      TIMESTAMPTZ NOT NULL,
  planned_start TIMESTAMPTZ,             -- после оптимизации маршрута
  status        TEXT NOT NULL,           -- booked, confirmed, en_route, done, no_show, moved, cancelled
  source        TEXT,                    -- bot, tma, web, operator
  rating        SMALLINT,
  rating_text   TEXT
);
```

## Правила
- Окно предлагается, только если после него остаётся ≥ 15 мин запаса.
- Срочные аварии имеют приоритет; если нужно снять запись — абоненту предлагаются 3 ближайших окна и бонус (настраивается).
- Подтверждение за сутки: «Ответьте 1, если всё в силе». Без ответа — звонок оператора или авто-звонок. Повторные неявки абонента → предоплата выезда.
- Утренняя оптимизация не выходит за рамки обещанных абонентам окон.

## Интерфейсы
- **Абонент:** бот / Mini App / сайт — календарь окон, кнопки «перенести», «отменить», статус «в пути».
- **Оператор:** тот же календарь в карточке абонента.
- **Диспетчер:** диаграмма Ганта по монтажникам, перетаскивание, карта маршрутов.
- **Монтажник (PWA):** маршрут дня, навигация, кнопки «выехал», «на месте», «готово».

## Интеграции
`tasks`, `notify`, склад, OSRM, модуль 04 (после расчёта стоимости), модуль 14 (подрядчики).

## Метрики
- Доля записей без участия оператора (цель > 50%).
- Неявки абонентов (цель < 5%).
- Работ на монтажника в день (рост).
- Километров на работу (снижение).
- Средняя оценка визита.

## Риски
- Неточные длительности работ ломают расписание — система учится на фактическом времени и корректирует нормативы раз в неделю.
- Если монтажники не отмечают статусы в приложении, оценки ETA бесполезны — статусы обязательны для закрытия заявки.

## MVP (2 недели)
Календарь окон по графикам монтажников и зонам (без учёта дороги) + бронь + напоминания в Telegram + перенос. Оптимизация маршрутов и ETA — вторым шагом.

## Как проверить
1. Запросить окна для адреса в зоне двух монтажников → окна обоих, сначала те, где монтажник уже рядом.
2. Забронировать последнее свободное окно двумя клиентами одновременно → второй получает «окно занято».
3. Создать срочную аварию → система предлагает перенос одной записи, абонент получает 3 новых окна.

## Зависимости
`tasks`, `notify`, `geo` (зоны, OSRM), склад, модули 04 и 14.
