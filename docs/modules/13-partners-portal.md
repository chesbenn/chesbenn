# 13. Портал партнёров: застройщики и управляющие компании

**Коротко:** отдельный кабинет для застройщиков и УК/ТСЖ. Застройщик заранее согласует сеть в новом ЖК и продаёт квартиры «с интернетом с первого дня»; УК сообщает о плановых отключениях и работах в доме, видит договоры и контакты провайдера, вызывает его на проблемы. Отношения из «звонков и бумажек» превращаются в процесс.

---

## Проблема
- **Новостройки:** провайдер узнаёт о новом доме, когда туда уже зашли крупные операторы по договору с застройщиком. Жильцы въезжают, а подключиться можно только к одному.
- **УК:** доступ в дома, ключи от подвалов, согласования работ, отключения света и воды, споры об электричестве — всё по телефону и письмам. Закон 2024 года запрещает брать плату за доступ, но на практике сотрудничество работает в 15–30% случаев.
- Провайдер не узнаёт заранее, что УК меняет щитки, красит подъезд (и срежет кабели) или отключает свет.

## Что делает

### Для застройщика
1. **Реестр строящихся объектов:** адрес, очереди, сроки сдачи, число квартир, контакт.
2. **Согласование проекта сети:** провайдер загружает проект слаботочки/ВОЛС, застройщик утверждает в портале.
3. **Предпродажа:** для покупателей квартир — ссылка «подключите интернет заранее» (предзаказ, ранняя цена).
4. **График монтажа** в доме до сдачи, доступ бригад.
5. **Статистика спроса** по дому (предзаказы) — для решения о стройке.

### Для управляющей компании
1. **Список домов** под управлением УК, где есть сеть провайдера: узлы, оборудование, контакты дежурных.
2. **Уведомления от УК:** плановые отключения света/воды, ремонт подъездов и щитков, замена лифтов → автоматически в модули 01 и 07.
3. **Заявки от УК:** «кабель провайдера висит в подъезде», «оборудование шумит», «нужен доступ для осмотра».
4. **Доступ в помещения:** кто, когда и зачем приходил (журнал), заявка на доступ провайдера, электронные ключи (если есть).
5. **Документы:** договоры размещения, расчёт электроэнергии (модуль 12), акты.
6. **Статус-страница по их домам:** аварии и работы.

## Кто пользуется
| Роль | Что делает |
|---|---|
| Застройщик | Объекты, проекты, предзаказы, график |
| Сотрудник УК / ТСЖ | Уведомления, заявки, доступ, документы |
| Менеджер провайдера по партнёрам | Ведёт отношения, отвечает на заявки |
| Инженер | Получает уведомления о работах в домах, согласовывает доступ |

## Как работает
```
Регистрация партнёра
  → менеджер провайдера создаёт организацию партнёра и приглашает сотрудников (e-mail/Telegram)
  → привязка домов: УК — по списку адресов (ГИС ЖКХ или вручную), застройщик — по объектам

УК сообщает об отключении света
  → форма: дома, дата/время, причина
  → событие ext.power.planned (source=uk_portal) → модуль 01 (уведомления абонентам, подавление)

УК сообщает о ремонте подъезда / щитков
  → событие ext.building.works → модуль 07: окно риска для оборудования в доме
  → инженеру: "проверить крепление кабелей до начала ремонта"

Заявка УК на провайдера
  → tasks (тип partner_request), SLA ответа 1 рабочий день
  → статус виден УК в портале

Застройщик: новый объект
  → объект → граф (building, status=construction)
  → модуль 04: расчёт стоимости подключения дома
  → публичная страница предзаказа → лиды
  → при достижении порога предзаказов → решение о стройке, график монтажа
  → при сдаче дома: предзаказы → заявки на подключение с записью (модуль 05)
```

## Модель данных
```sql
CREATE TABLE partner_org (
  id          BIGSERIAL PRIMARY KEY,
  kind        TEXT NOT NULL,              -- uk, tsj, developer, landlord
  name        TEXT NOT NULL,
  inn         TEXT,
  contacts    JSONB,
  agreement_ids BIGINT[]
);

CREATE TABLE partner_building (
  partner_id  BIGINT REFERENCES partner_org(id),
  building_id BIGINT REFERENCES graph_node(id),
  role        TEXT NOT NULL,              -- manages, builds, owns
  PRIMARY KEY (partner_id, building_id)
);

CREATE TABLE construction_project (
  id           BIGSERIAL PRIMARY KEY,
  developer_id BIGINT REFERENCES partner_org(id),
  building_id  BIGINT REFERENCES graph_node(id),
  name         TEXT,
  flats        INT,
  handover_on  DATE,
  network_design_ids TEXT[],
  design_status TEXT,                     -- draft, submitted, approved, built
  preorders    INT DEFAULT 0
);

CREATE TABLE partner_request (
  id          BIGSERIAL PRIMARY KEY,
  partner_id  BIGINT REFERENCES partner_org(id),
  building_id BIGINT,
  kind        TEXT NOT NULL,              -- outage_notice, building_works, issue, access_request
  payload     JSONB,
  task_id     BIGINT,
  status      TEXT NOT NULL,
  created_at  TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE access_log (
  id          BIGSERIAL PRIMARY KEY,
  building_id BIGINT,
  room        TEXT,                       -- подвал, чердак, щитовая
  person      TEXT,
  purpose     TEXT,
  task_id     BIGINT,
  entered_at  TIMESTAMPTZ, left_at TIMESTAMPTZ
);
```

## Правила
- Партнёр видит только свои дома и только свои заявки; никаких данных абонентов (только агрегаты: «в доме 140 подключённых квартир» — по согласованию).
- Сообщения УК об отключениях имеют приоритет над данными энергетиков (они точнее по конкретному дому).
- Ответ на заявку УК — не позже 1 рабочего дня, иначе эскалация менеджеру.

## Интерфейсы
- **Веб-портал партнёра** (отдельный вход, простой интерфейс): мои дома, сообщить об отключении/работах, заявки, документы.
- **Telegram-бот для сотрудников УК:** быстрые сообщения «завтра отключаем свет в доме …».
- **Страница предзаказа** для покупателей новостройки.
- **Панель менеджера по партнёрам:** все организации, заявки, документы, проблемы.

## Интеграции
`graph`, `geo`, `tasks`, `notify`, модули 01, 04, 05, 07, 12; ГИС ЖКХ (список домов УК, если доступно).

## Метрики
- Доля новостроек в зоне присутствия, где провайдер зашёл до сдачи дома.
- Доля отключений света, о которых узнали заранее от УК.
- Число заявок УК и среднее время ответа.
- Число конфликтов с УК (снижение).

## Риски
- УК не захотят пользоваться ещё одним порталом — главное упрощение: Telegram-бот и ответ провайдера в течение дня; выгода для УК — меньше жалоб жильцов.
- Застройщики часто имеют эксклюзивные договоры с крупными операторами — портал помогает только там, где есть возможность конкуренции (закон о доступе в МКД).

## MVP (2 недели)
Портал УК: мои дома, «сообщить об отключении» (→ модуль 01), заявки с ответом. Застройщики и предзаказы — вторым шагом.

## Как проверить
1. Сотрудник УК сообщает об отключении света в доме → абоненты дома получают уведомление, алерты подавлены на окно.
2. УК создаёт заявку «кабель висит» → задача у провайдера, статус виден УК.
3. Застройщик добавляет объект → появляется страница предзаказа; 30 предзаказов → уведомление менеджеру.

## Зависимости
`graph`, `geo`, `tasks`, `notify`, `auth` (внешние пользователи), модули 01, 04, 05, 07, 12.
