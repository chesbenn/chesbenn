# 03. Детектор краж кабеля и вандализма

**Коротко:** платформа по характерному «почерку» событий отличает кражу кабеля или вандализм от обычной аварии: ночью, без отключения света, одновременно пропадает целый участок, часто в одном и том же месте. Дежурный сразу получает тревогу с точкой на карте, а не утром — заявку «нет интернета у 80 абонентов».

---

## Проблема
- Кабель (особенно медный и воздушные оптические линии) воруют и режут: на цветмет, по ошибке, из вредности, в ходе конкурентной борьбы.
- Провайдер узнаёт об этом утром по звонкам; к этому моменту следов уже нет, а повреждение тянет за собой многочасовой ремонт.
- Повторные кражи на одних и тех же участках никто не анализирует.

## Что делает
1. **Распознаёт почерк кражи** по событиям сети: одновременная потеря связи на участке, LOS (а не dying gasp), ночное время, нет плановых работ и отключения света.
2. **Определяет место обрыва** по графу: общий участок кабеля/сплиттер/опорный пролёт для всех пострадавших.
3. **Подаёт тревогу** дежурному и (опционально) охране/ЧОП с координатами и схемой.
4. **Ведёт журнал инцидентов** с фото, протоколами, суммами ущерба — для заявлений в полицию и страховки.
5. **Строит карту «горячих точек»** и рекомендует меры: камеры, датчики открытия, перенос трассы, защитные короба.
6. **Готовит документы:** заявление в полицию по шаблону, расчёт ущерба (материалы + работа + компенсации абонентам).
7. **Интегрируется с датчиками:** датчики открытия ящиков/шкафов, вибрационные/акустические датчики на опорах (если установлены), камеры узлов.

## Кто пользуется
| Роль | Что делает |
|---|---|
| Дежурный NOC | Получает тревогу, вызывает бригаду/охрану |
| Служба безопасности / ЧОП | Получает координаты, выезжает |
| Руководитель | Журнал ущерба, карта горячих точек, решения о защите |
| Юрист | Документы для полиции и страховой |

## Как работает
```
События сети (net.onu.los, net.port.down, net.device.unreachable)
   → окно корреляции 120 секунд
   → поиск общего предка в графе для всех потерявших связь (кабель / сплиттер / пролёт)
   → проверки:
        есть ли dying gasp? (да → это свет, не кража)
        есть ли активное плановое окно работ? (да → не кража)
        есть ли отключение света по модулю 01? (да → не кража)
        время суток (ночь +), история участка (были кражи +), тип линии (воздушная +, медь +)
        датчик открытия ящика сработал? (+ много)
   → оценка вероятности "кража/вандализм" (0..1)
   → ≥ 0.6 → тревога security_alert: карта, участок, абоненты, ближайшие камеры
   → < 0.6 → обычный инцидент сети, с пометкой "возможна кража"
   → после ремонта монтажник подтверждает причину: кража / вандализм / авария / другое
   → подтверждение пополняет статистику и обучает оценку
```

## Данные
| Данные | Источник |
|---|---|
| Потери связи ONU/портов | OLT, коммутаторы (трапы, syslog, опрос) |
| Топология участков (кабели, пролёты, сплиттеры) | Граф (Userside/ГИС/ручной ввод) |
| Отключения света, плановые работы | Модули 01 и 07 |
| Датчики открытия, вибрации | GPIO/Modbus/SNMP датчиков в шкафах, контроллеры узлов |
| Подтверждённые причины | Закрытие заявок монтажниками |

## Модель данных
```sql
CREATE TABLE security_incident (
  id               BIGSERIAL PRIMARY KEY,
  detected_at      TIMESTAMPTZ NOT NULL,
  segment_node_id  BIGINT REFERENCES graph_node(id),   -- участок/объект
  geom             geometry(Geometry, 4326),
  probability      REAL NOT NULL,
  signals          JSONB NOT NULL,      -- какие признаки сработали и с каким весом
  subscribers_hit  INT,
  status           TEXT NOT NULL,       -- alert, dispatched, confirmed_theft, confirmed_vandalism,
                                        -- false_alarm, accident
  damage_materials NUMERIC(12,2),
  damage_labor     NUMERIC(12,2),
  damage_compens   NUMERIC(12,2),       -- компенсации абонентам (модуль 10)
  police_report_no TEXT,
  photo_ids        TEXT[],
  task_id          BIGINT
);

CREATE TABLE segment_risk (
  segment_node_id  BIGINT PRIMARY KEY REFERENCES graph_node(id),
  incidents_12m    INT,
  last_incident_at TIMESTAMPTZ,
  risk_score       REAL,
  protection       TEXT[]               -- camera, sensor, conduit, relocated
);
```

## Правила и алгоритмы
Оценка вероятности — сначала простая взвешенная сумма (понятная и проверяемая), позже — модель на подтверждённых случаях.

| Признак | Вес |
|---|---|
| Все потери — LOS, нет dying gasp | +0,25 |
| Время 23:00–05:00 | +0,15 |
| Участок воздушный или медный | +0,10 |
| На участке были кражи за 12 мес | +0,20 (×число, макс. +0,30) |
| Сработал датчик открытия/вибрации | +0,40 |
| Есть плановые работы / отключение света | −1,0 (исключение) |
| Потери растянуты во времени > 5 мин | −0,20 (похоже на деградацию) |

## Интерфейсы
- **Тревога** в Telegram дежурному и охране: карта, участок, число абонентов, кнопки «выехали», «ложная», «подтверждено».
- **Панель безопасности:** журнал инцидентов, карта горячих точек, ущерб по месяцам, рекомендации.
- **Генератор документов:** заявление в полицию, акт об ущербе (PDF).

## Интеграции
`graph`, `telemetry`, `tasks`, `notify`, модули 01, 07, 10; контроллеры датчиков; камеры (ссылка на поток/архив за время события).

## Метрики успеха
- Время от обрыва до тревоги (цель < 3 мин).
- Доля ночных краж, по которым был выезд в течение 30 мин.
- Повторные кражи на защищённых участках (снижение).
- Сумма ущерба в месяц (снижение).

## Риски
- Ложные тревоги ночью раздражают охрану — порог настраивается, первые месяцы режим «только NOC».
- Нет точной топологии кабелей — место определяется до сплиттера/коммутатора, а не до пролёта.

## MVP (2 недели)
Корреляция LOS по общему сплиттеру/коммутатору + проверка на свет и плановые работы + ночная тревога в Telegram. Журнал ущерба и документы — вторым шагом.

## Как проверить
1. Симулятор в 03:00 обрывает кабель за сплиттером на 24 ONU (все LOS) → тревога с вероятностью ≥ 0,6.
2. Тот же сценарий, но с dying gasp → тревоги нет, инцидент «нет света».
3. Тот же сценарий во время планового окна работ → тревоги нет.

## Зависимости
`graph` (участки и топология), коннекторы OLT/коммутаторов, модули 01 и 07, `notify`, `tasks`.
