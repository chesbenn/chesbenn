# Модули платформы провайдера

16 модулей с полным разбором: что делает, кто пользуется, как работает по шагам, данные, таблицы БД, правила, интерфейсы, интеграции, метрики, риски, MVP и сценарии проверки.

**Главное правило: абоненту ничего не нужно делать.** Все модули работают на данных, которые у провайдера уже есть: биллинг, RADIUS, OLT, коммутаторы, BRAS/шейпер, мониторинг, ACS. Пользователи модулей — сотрудники провайдера (и для модуля 13 — партнёры: УК и застройщики).

Как всё это собирается в одну работающую платформу, описано в [`../ARCHITECTURE.md`](../ARCHITECTURE.md).

## Как модули связаны

```
            Биллинг · RADIUS · OLT · Коммутаторы · BRAS · Мониторинг · ACS
                                     │
                         граф «абонент ↔ сеть» + телеметрия
                                     │
     ┌──────────────┬────────────────┼─────────────────┬────────────────┐
     ▼              ▼                ▼                 ▼                ▼
 05 Автосверка  02 Проблемы до   01 Отключения    04 Прогноз      08 Аплинки
 (деньги)       звонка           света            ёмкости         и SLA
     │              │                │                 │                │
     └──────────────┴────► 06 Карточка абонента ◄──────┴────────────────┘
                                     │
          03 Кражи ── 07 Плановые работы ── 11 Критичные ── 13 УК/застройщики
                                     │
                           10 Стоимость аварий
                                     │
                14 Подрядчики ── 09 Б/у оборудование ── 12 Энергоучёт
```

## Рекомендуемый порядок
1. **05 Автосверка** — за неделю показывает потери выручки в рублях; обычно окупает всю платформу.
2. **06 Карточка + 02 Проблемы до звонка** — провайдер видит всё про каждого абонента и находит проблемы первым.
3. **01 Отключения света + 07 Плановые работы + 11 Критичные** — порядок в авариях.
4. **04 Ёмкость + 10 Стоимость аварий** — планирование на цифрах.
5. **03, 08, 09, 12, 13, 14, 15, 16** — по потребности.

Все модули используют общий фундамент (граф, шина событий, заявки, уведомления), поэтому строятся после этапов 0–2 из [`ARCHITECTURE.md`](../ARCHITECTURE.md#7-порядок-строительства).
