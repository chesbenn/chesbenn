# 12. Энергоучёт узлов и расчёты за электричество

**Коротко:** платформа знает, сколько электричества потребляет каждый узел связи (в подвале, на чердаке, в шкафу на опоре), кто за него платит и по какому договору. Она решает две частые проблемы: споры с управляющими компаниями («ваше оборудование жжёт наш свет») и непонимание реальной стоимости содержания сети.

---

## Проблема
- Оборудование в многоквартирных домах питается от общедомовой сети. УК требуют компенсацию, иногда выставляют завышенные суммы или угрожают отключить.
- Провайдер не знает, сколько реально потребляет каждый узел; договоры с УК о компенсации ведутся в Excel или не ведутся вообще.
- В некоторых местах электричество оплачивается по отдельным счётчикам — счета проверяются вручную.
- При росте тарифов на электроэнергию неясно, сколько стоит содержание каждого узла.

## Что делает
1. **Реестр точек питания:** узел → от чего питается (общедомовая сеть, свой счётчик, опора), договор, кто платит, тариф.
2. **Расчёт потребления:** по паспортной мощности оборудования + фактические данные (SNMP с ИБП/PDU, если есть; умные розетки/счётчики с Modbus/MQTT).
3. **Реестр договоров с УК:** сумма компенсации, порядок расчёта, сроки, акты.
4. **Проверка счетов:** сравнивает выставленную сумму с расчётным потреблением × тариф; подсвечивает завышения.
5. **Автоматические документы:** расчёт потребления по каждому дому для УК, акты сверки.
6. **Аналитика:** стоимость электричества на узел и на абонента, самые «прожорливые» узлы, экономия от замены старого оборудования.
7. **Контроль ИБП:** состояние батарей (если ИБП с SNMP) — связь с модулем 01.

## Кто пользуется
| Роль | Что делает |
|---|---|
| Бухгалтер / финансист | Договоры с УК, проверка счетов, акты |
| Инженер | Состав оборудования узла, мощность, ИБП |
| Руководитель | Затраты на электричество, решения о модернизации |
| УК (партнёр) | Получает прозрачный расчёт (через портал) |

## Как работает
```
Наполнение
  → graph: состав оборудования каждого node_site (OLT, коммутаторы, ИБП, медиаконвертеры)
  → справочник моделей: паспортная мощность (Вт), типичная загрузка
  → реестр точек питания и договоров (ввод, импорт из Excel)

Расчёт (ежемесячно)
  → для каждого узла:
        если есть измерение (ИБП/PDU/счётчик) → фактические кВт·ч из telemetry
        иначе → Σ(мощность × коэфф_загрузки) × часы_в_месяце × 1.1 (потери БП)
  → стоимость = кВт·ч × тариф (по региону/договору)
  → сравнение с договорной компенсацией и выставленными счетами
  → расхождение > 20% → задача финансисту "проверить счёт УК X"
  → генерация расчёта для УК (PDF) с перечнем оборудования и формулой

Модернизация
  → для узла: текущее потребление vs вариант с новым оборудованием → экономия/год
```

## Модель данных
```sql
CREATE TABLE power_point (
  id            BIGSERIAL PRIMARY KEY,
  node_site_id  BIGINT REFERENCES graph_node(id),
  supply_kind   TEXT NOT NULL,              -- house_common, own_meter, pole, datacenter
  payer         TEXT NOT NULL,              -- provider, uk, landlord
  counterparty  TEXT,                       -- УК / арендодатель
  contract_id   BIGINT,
  tariff_rub_kwh NUMERIC(8,4),
  meter_id      TEXT,                       -- если свой счётчик
  measured_by   TEXT                        -- ups_snmp, pdu, smart_meter, estimate
);

CREATE TABLE energy_contract (
  id            BIGSERIAL PRIMARY KEY,
  counterparty  TEXT NOT NULL,
  kind          TEXT NOT NULL,              -- fixed_monthly, by_calculation, by_meter
  amount_month  NUMERIC(10,2),
  formula       TEXT,
  starts_on     DATE, ends_on DATE,
  buildings     BIGINT[],
  document_ids  TEXT[]
);

CREATE TABLE energy_monthly (
  power_point_id BIGINT REFERENCES power_point(id),
  month          DATE,
  kwh            NUMERIC(10,2),
  source         TEXT,                      -- measured, estimated
  cost_calc      NUMERIC(10,2),
  cost_billed    NUMERIC(10,2),             -- выставлено контрагентом
  diff_pct       NUMERIC(6,2),
  PRIMARY KEY (power_point_id, month)
);

CREATE TABLE device_model_power (
  model        TEXT PRIMARY KEY,
  watts_nominal NUMERIC(8,1),
  load_factor  NUMERIC(4,2) DEFAULT 0.6
);
```

## Правила
- Оценка по паспорту помечается как «оценка»; при спорах рекомендуется поставить счётчик/умную розетку (окупается при расхождениях > 1 000 ₽/мес).
- Если УК выставляет сумму > расчёта на 50%+ два месяца подряд — задача юристу.
- Тарифы на электроэнергию обновляются раз в полгода (регулируемые).

## Интерфейсы
- **Карта узлов** с цветом по стоимости электричества.
- **Таблица договоров с УК:** сумма, срок, расхождения.
- **Проверка счетов:** ввод суммы счёта → мгновенное сравнение.
- **Документ для УК:** «Расчёт потребления электроэнергии оборудованием связи в доме …».

## Интеграции
`graph` (оборудование узлов), `telemetry` (ИБП/PDU по SNMP, счётчики по Modbus/MQTT), портал УК (модуль 13 и партнёры), `files`, модули 01 и 10.

## Метрики
- Сумма завышений в счетах УК, выявленная и оспоренная.
- Стоимость электричества на абонента в месяц.
- Число конфликтов с УК (снижение).

## Риски
- Паспортные мощности завышены относительно реальных — использовать коэффициент загрузки и выборочные измерения для калибровки.

## MVP (1–2 недели)
Реестр узлов и договоров с УК + расчёт по паспортной мощности + документ для УК. Измерения и проверка счетов — вторым шагом.

## Как проверить
1. Узел из демо: OLT 120 Вт + 2 коммутатора по 20 Вт → расчёт кВт·ч и стоимость за месяц.
2. Ввести счёт УК на 2× больше расчёта → подсветка и задача финансисту.
3. Сгенерировать документ для УК → PDF с перечнем оборудования и формулой.

## Зависимости
`graph`, `telemetry`, справочник моделей, `files`, договоры (модуль 13 — портал партнёров).
