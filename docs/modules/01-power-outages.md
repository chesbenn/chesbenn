# 01. Плановые и аварийные отключения электричества

**Коротко:** платформа заранее знает, где и когда отключат свет (данные энергетиков и управляющих компаний), и по сигналам ONU видит, где свет пропал прямо сейчас. Абоненты получают объяснение «это не интернет, это свет», ложные алерты подавляются, а дежурные не бегут чинить то, что не сломано.

---

## Проблема
- Когда в доме пропадает электричество, у провайдера «падают» десятки ONU и коммутатор в подвале. NOC видит аварию, поддержка получает шквал звонков, иногда выезжает бригада — а чинить нечего.
- Энергетики публикуют графики плановых отключений (на сайтах сетевых компаний, в ЕДДС, у управляющих компаний), но провайдер их не читает.
- Абонент не понимает, что проблема в электричестве у роутера или в подъезде, и винит провайдера.

## Что делает
1. **Собирает плановые отключения** с сайтов энергокомпаний, из рассылок УК, из портала партнёров (см. модуль 13 и портал УК).
2. **Сопоставляет адреса** отключений с домами в графе.
3. **За сутки и за час** до отключения рассылает абонентам этих домов сообщение.
4. **На время отключения подавляет алерты** по оборудованию в этих домах (вместо 40 алертов — одна запись «плановое отключение света»).
5. **Определяет внезапные отключения света** по сигналам ONU «dying gasp» (ONU сообщает, что теряет питание).
6. **Отличает «свет» от «обрыва»:** dying gasp у многих ONU одного дома/улицы = нет света; LOS (потеря сигнала) без dying gasp = обрыв кабеля.
7. **Отвечает абонентам автоматически** (бот, IVR, оператору на экран): «В вашем доме нет электричества с 14:05. Наша сеть в порядке».
8. **После восстановления** проверяет, что все ONU вернулись, и создаёт заявки на те, что не вернулись (сгорел блок питания и т.п.).
9. **Карта отключений** для руководства и (по желанию) для УК и энергетиков.

## Кто пользуется
| Роль | Что видит / делает |
|---|---|
| NOC-инженер | Карта отключений, подавленные алерты, список невернувшихся ONU |
| Оператор поддержки | Подсказка при звонке: «у абонента нет света» |
| Абонент | Уведомление заранее и объяснение во время сбоя |
| Руководитель | Статистика: сколько звонков и выездов сэкономлено |
| УК / энергетики (партнёр) | Карта отключений по их территории (по договору) |

## Как работает

### Поток 1. Плановое отключение
```
[сайт энергетиков] → коннектор external/power → парсинг → нормализация адресов (geo)
   → событие ext.power.planned {адреса, начало, конец, источник}
   → модуль: поиск домов в графе → список абонентов
   → notify: за 24 ч и за 1 ч ("Завтра с 10:00 до 16:00 в вашем доме отключат свет")
   → создание "окна подавления" алертов на время отключения
   → после конца окна: проверка возврата ONU
```

### Поток 2. Внезапное отключение
```
[OLT] → syslog/трап "dying gasp" ONU → коннектор olt-* → событие net.onu.dying_gasp
   → модуль собирает события за скользящее окно 60 секунд
   → группировка по дому/подъезду/улице (через граф)
   → решение: "нет света" если в доме ≥ 60% ONU прислали dying gasp
              или ≥ 3 ONU в доме и все — dying gasp, а не LOS
   → инцидент типа power_outage (не network_outage!)
   → подавление алертов по коммутаторам в этом доме
   → автоответ абонентам, обновление статус-страницы
   → ожидание возврата: когда ≥ 90% ONU вернулись — инцидент закрыт
   → оставшиеся ONU через 30 мин → заявка "проверить ONU/БП"
```

### Поток 3. Звонок абонента
```
звонок/сообщение → поиск абонента → есть ли активный power_outage на его здании?
   да → ответ "нет электричества с HH:MM, по данным энергетиков до HH:MM"
   нет → обычная диагностика
```

## Данные: откуда берутся
| Данные | Источник | Как часто |
|---|---|---|
| Плановые отключения | Сайты сетевых компаний (Россети и региональные), ЕДДС, сайты УК, ручной ввод, портал партнёров | Каждые 2 часа |
| Dying gasp, LOS | Syslog и SNMP-трапы OLT (BDCOM, C-Data, Huawei, ZTE, V-SOL — у всех есть) | В реальном времени |
| Привязка ONU → дом | Граф (биллинг + OLT) | Постоянно |
| Коммутаторы в домах | Граф (SNMP, LLDP) + Zabbix | Постоянно |

## Модель данных
```sql
CREATE TABLE power_outage (
  id            BIGSERIAL PRIMARY KEY,
  kind          TEXT NOT NULL,          -- planned | detected
  source        TEXT NOT NULL,          -- energy_site:<имя>, uk_portal, manual, onu_dying_gasp
  source_ref    TEXT,                   -- id/ссылка на исходную запись
  starts_at     TIMESTAMPTZ NOT NULL,
  ends_at       TIMESTAMPTZ,            -- плановое или фактическое
  status        TEXT NOT NULL,          -- scheduled | active | restoring | closed | cancelled
  raw_text      TEXT,                   -- исходный текст объявления
  created_at    TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE power_outage_building (
  outage_id     BIGINT REFERENCES power_outage(id),
  building_id   BIGINT REFERENCES graph_node(id),
  match_score   REAL,                   -- уверенность сопоставления адреса
  onu_total     INT,
  onu_lost      INT,
  onu_restored  INT,
  PRIMARY KEY (outage_id, building_id)
);

CREATE TABLE alert_suppression (
  id           BIGSERIAL PRIMARY KEY,
  reason       TEXT NOT NULL,           -- power_outage:<id>, maintenance:<id>
  node_ids     BIGINT[] NOT NULL,       -- узлы графа (дома, коммутаторы)
  starts_at    TIMESTAMPTZ NOT NULL,
  ends_at      TIMESTAMPTZ NOT NULL
);
```

## Правила и алгоритмы
- **Парсинг объявлений.** Тексты энергетиков неструктурированы («ул. Ленина д. 5-17 нечётные, пер. Садовый»). Два шага: 1) правила (регулярные выражения для типовых форматов); 2) если правила не справились — LLM извлекает список адресов в JSON, результат проходит нормализацию в `geo`. Сопоставление с уверенностью < 0,8 — в очередь на ручную проверку.
- **Детектор «нет света».** Порог настраивается. По умолчанию: окно 60 с; дом считается обесточенным, если `dying_gasp ≥ 3` и `dying_gasp / onu_total ≥ 0,6`. Для частных домов (1 ONU) — группировка по улице/трансформаторной подстанции, если она известна.
- **Свет vs. обрыв.** LOS без dying gasp у ONU одного сплиттера → обрыв волокна (инцидент сети). Dying gasp → питание. Смешанная картина → инцидент «неясно», в NOC.
- **Подавление алертов** не удаляет их: они пишутся в журнал с пометкой «подавлено: отключение света №…».
- **Тихие часы:** уведомления о плановых отключениях не отправляются с 22:00 до 9:00 (кроме случаев, когда отключение начинается раньше 9:00 — тогда вечером накануне).

## Интерфейсы
- **Веб-панель:** карта с закрашенными домами (плановые — жёлтые, активные — красные, восстановление — синие); список отключений; очередь ручной проверки адресов.
- **Экран оператора:** плашка «Нет электричества в доме с 14:05» в карточке абонента.
- **Бот/Mini App:** автоответ и подписка «предупреждать о плановых отключениях».
- **API:** `GET /power-outages?bbox=...`, `POST /power-outages` (ручной ввод и портал партнёров).

## Интеграции
- `connectors/external/power_<регион>` — по одному парсеру на сайт энергокомпании (их немного в каждом регионе).
- OLT-коннекторы: обязательна поддержка dying gasp из syslog/трапов.
- Zabbix: подавление через maintenance API (если используется Zabbix).
- Статус-страница и `notify`.

## Метрики успеха
- Доля звонков во время отключений света, закрытых автоответом (цель > 70%).
- Число выездов «нет неисправности» из-за отключения света (цель → 0).
- Число алертов NOC во время отключений (снижение в 10+ раз).
- Время от отключения до первого автоответа (цель < 2 мин).

## Риски и ограничения
- Не все ONU отправляют dying gasp (дешёвые модели, отключённая функция) — для них только косвенный признак (массовое падение без LOS).
- Сайты энергетиков меняют вёрстку — парсеры ломаются. Нужен мониторинг «парсер не находил данных 3 дня».
- Если коммутатор в доме на ИБП, а ONU абонентов нет — картина смешанная; правило учитывает тип подключения.

## MVP (2–3 недели)
1. Dying gasp из syslog одного типа OLT → детектор → инцидент «нет света» → сообщение в Telegram-чат NOC.
2. Ручной ввод плановых отключений + рассылка абонентам.
3. Плашка в карточке абонента.

Дальше: парсеры сайтов энергетиков, подавление алертов в Zabbix, карта для партнёров.

## Как проверить (e2e на симуляторе)
1. Симулятор отключает свет в доме из 40 ONU → 30 dying gasp за 20 секунд.
2. Ожидаем: один инцидент `power_outage`, ноль инцидентов `network_outage`, алерты коммутатора подавлены.
3. Абонент из этого дома пишет боту «нет интернета» → получает ответ про электричество.
4. Симулятор возвращает свет, 2 ONU не возвращаются → через 30 мин две заявки.

## Зависимости
`graph`, `geo`, `notify`, `tasks`, коннекторы OLT (syslog/трапы), `external/power`, статус-страница.
